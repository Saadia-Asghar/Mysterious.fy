# Grafana visualization

Grafana displays. It never computes anomalies, correlation or RCA.

## What is provisioned

| File | Purpose |
|---|---|
| `provisioning/datasources/zabbix.yml` | `zabbix` data source (Zabbix plugin): live device metrics |
| `provisioning/datasources/nms-api.yml` | `nms-api` data source (Infinity plugin): incidents, RCA, tickets, remediation, verification from the integration API |
| `provisioning/plugins/zabbix-app.yml` | Enables the Zabbix app plugin (its data source needs it) |
| `provisioning/dashboards/nms.yml` | Loads every JSON in `dashboards/` into folder **NMS** |
| `dashboards/nms-operations.json` | **NMS Operations** dashboard, generated by `scripts/build_grafana_dashboard.py` |

Edit the script, then run `python scripts/build_grafana_dashboard.py`. A test fails if the JSON and the script drift apart.

## NMS Operations dashboard (M13)

1. **Overview**: open, awaiting approval, verifying, escalated, resolved, alert reduction.
2. **Incidents**: one row per correlated incident with affected devices, probable cause and why, osTicket number, remediation and Zabbix health (colour coded).
3. **Self-healing and verification**: every execution, the policy decision, approver, and the last Zabbix verification.
4. **Anomalies**: flagged readings from `robust_zscore_v1`.
5. **Device health**: availability, latency and packet loss from Zabbix, for the selected `$group` and `$host` (multi-select). One dashboard for every device type (M4: no per-camera dashboards).

## Integration API feeds

`GET /grafana/summary`, `GET /grafana/incidents[?status=]`, `GET /grafana/executions`, plus `GET /intelligence/anomalies?only_anomalies=true`. Grafana in Docker reaches the API on the host through `NMS_API_URL` (default `http://host.docker.internal:8000`), so run the API with `--host 0.0.0.0`.

## Assumptions to check on first run

- Device panels use the Zabbix built-in ICMP items (`ICMP ping`, `ICMP response time`, `ICMP loss`) from the "ICMP Ping" template. Adjust the regex in the script if your templates name them differently.
- Plugin query formats follow the Zabbix plugin 4.x and Infinity 2.x JSON models.
